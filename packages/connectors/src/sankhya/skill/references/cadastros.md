# Cadastros

Register data that other reads point to. Read `empresas` first: the sales, finance and logistics reads need a company code. Every list here starts at page 0 and says with `temMais` if there is another.

- `empresas`: the companies (code, trade name, legal name). Takes no filter.
- `clientes`: the customers (document, name, address, and the company's own `AD_` fields in `camposAdicionais`). `codigoCliente` comes as text, `tipo` as `F` or `J`, and `endereco.cidade` is an object with the city's name, IBGE code and state. `dataHoraAlteracao` (`dd/mm/aaaa hh:mm`) keeps what changed after it. The read sorts by code, so the pages are stable. Suppliers are not here: `buscarParceiros` with `papel: fornecedor` finds them (more in `tabelas`). It does not filter by name or document: use `buscarParceiros`.
- `vendedores`: the salespeople (name, manager, commissions, active). `tipo` may be a number in one row and text in another. `modifiedSince` (`dd/mm/aaaa hh:mm`).
- `tiposOperacao`: the operation types (TOP): code, name, movement type, active. `tipoMovimento` filters by movement. Which TOPs are a sale, a return or a purchase is this company's choice: read the movement type and ask, never assume from the name. On some companies Sankhya itself refuses the first page with a 400; then read the operation types through the read door, table `TGFTOP` (confirm its columns in the dictionary, and join on the version a document stored, `DHTIPOPER`). The cause is in Sankhya: `/v1/tipos-operacao` fails a whole page when one TOP, even an inactive one, holds a `TIPMOV` outside Sankhya's own dictionary, and `tipoMovimento` filters never return such a TOP. The route's pages also have no stable order, so rows skip and repeat. Never build an app on this route.
- `buscarParceiros`: finds partners, customers and suppliers alike, in one call. Filters, all optional and combined with AND: `nome` (2 to 60 characters, part of the name or the legal name, case and accent ignored), `documento` (the 11 digits of a CPF or the 14 of a CNPJ), `codigos` (up to 100), `deCodigo` and `ateCodigo`, `papel` (`cliente` or `fornecedor`), `ativo`, and the paging: `limite` (1 to 100, 20 when absent) and `depoisDe` (the last `codigoParceiro` read). Rows come in code order as `codigoParceiro`, `nome`, `razaoSocial`, `documento`, `tipoPessoa`, `ativo`, `cliente`, `fornecedor`. Without a filter it lists every partner. Confirm in this company's data how a document is stored before relying on `documento`.
- `buscarVendedores`: finds salespeople by `nome` (the nickname), `codigos`, `ativo`, with the same paging (`limite`, `depoisDe`). Rows: `codigoVendedor`, `apelido`, `ativo`.
- `naturezas`: the financial natures (code, name, parent, analytic).
- `centrosResultado`: the result centers (code, name, parent, analytic, active).
